# V20 — Feedback-to-Action and Faculty Authoring

V20 adds a local-first workflow for turning bounded, purpose-defined feedback into tracked improvement actions and versioned faculty-authored content.

## Quick start

```bash
python usiphus_v20.py --self-test
python usiphus_v20.py --input examples/v20/workflow.json --output-dir build-v20
python -m unittest tests.test_v20_feedback_authoring -v
```

Outputs: a privacy-minimized JSON report, structured authored-content JSON export, static HTML release preview and CSV action queue.

## Feedback-to-action

Each feedback record includes role, purpose, notice acknowledgement, restricted visibility, timezone-aware submission and retention dates, and optional confidence. It may link to an artifact. Each action must link to known feedback and records a next step, owner label, due date, status and (when completed) completion evidence and follow-up outcome.

Reports intentionally do not echo feedback or comment text. Basic pattern checks flag possible email addresses, phone numbers and long numeric identifiers, but they are not reliable de-identification. Review and redact content before it enters any shared workflow. Do not submit patient identifiers, learner identifiers, clinical records or sensitive personal data to fixtures or examples. Configure lawful basis/consent where applicable, role-based access, secure storage, retention and deletion outside this local batch tool.

Confidence and satisfaction are reflection signals only, not measures of learning or competence. Keep formative feedback separate from summative grading.

## Faculty authoring

Versioned artifacts support cards, cases, objectives, evidence links, mappings, challenge packs, OSCE stations and MCQs. Comments bind to an exact artifact version. The report computes field-level version differences and a release preview. An artifact marked approved requires reviewer label and timezone-aware review timestamp; labels are not authenticated identities. The tool does not itself perform the approval or verify clinical correctness.

## Export boundary

V20 emits structured JSON, CSV and accessible-baseline static HTML preview using the Python standard library. PDF/PPTX export adapters are deliberately deferred until a real faculty template, accessibility workflow and dependency/maintenance decision are agreed; do not claim those formats are generated by this milestone. HTML preview is not an approved release. Final publication must use the governed V16 release workflow after explicit faculty sign-off.

## Pilot exit criteria

Pilot with synthetic content first. Faculty should demonstrate that feedback can be triaged into owned actions, actions can be closed with evidence and a follow-up outcome, version diffs are understandable, and review queues do not expose feedback to unauthorized roles. Record time-to-triage, action closure, repeat themes and authoring friction as aggregated workflow measures only. Review accessibility, retention/deletion and data access before any real learner feedback is collected.
